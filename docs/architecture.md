```
                ┌──────────────────────────────────────────────┐
   CLI ────────▶│ cli.py                                       │
 python -m      │ tick / dry-run / gardener / scan / selftest  │
 infinigrow     └───────────────┬──────────────────────────────┘
                               │
        ┌──────────────────────┼───────────────────────┬──────────────────┐
        ▼                      ▼                       ▼                  ▼
  ┌───────────┐        ┌──────────────┐        ┌────────────┐    ┌─────────────┐
  │ scheduler │        │   engine     │        │   rules    │    │   garden    │
  │ triggers  │        │ tick/reconcile│       │ static_scan│    │  gardener   │
  │（对外门面）│        │/sprout_*/    │        │（零 token） │    │（免疫系统）  │
  │           │        │ org_trigger  │        │            │    │             │
  └─────┬─────┘        └──────┬───────┘        └─────┬──────┘    └──────┬──────┘
        │  （只是转发）        │                      │                  │
        └─────────────────────┴──────────┬───────────┴──────────────────┘
                                         ▼
                              ┌────────────────────┐
                              │      ledger        │  ← 唯一写盘层（原子替换 + 越界守卫）
                              │  store.py          │
                              └─────────┬──────────┘
                                        ▼
                              ┌────────────────────┐
                              │       core         │  ← 唯一与机器相关的层
                              │ paths/config/encoding│     （状态根、配置、编码）
                              └────────────────────┘
```

**组织段触发判据为什么在 `engine/` 而不是 `scheduler/`**：拍循环**自己必须查它**。
上一代的病根之一就是「语义判断段没有调度入口」——判据与工具都写好了，没人调用，
诊断产出后就此过期。判据若只活在外部调度器里，拍循环就看不见「我该看语义层了」。
`scheduler/triggers.py` 因此降级为**对外门面**（给计划任务/看护脚本用的稳定入口），
实现与单一事实源在 `engine/org_trigger.py`；每拍算出结果后写 `state/org-due.json`
并进本拍返回值，让「该跑了」这件事**不可能被静默忽略**。

## 分层规则

1. **依赖只向下**：`core → ledger → engine → rules/garden/scheduler → cli`。
   上层可以 import 下层；下层不许 import 上层（有循环就说明切错了）。
2. **写盘只经过 `ledger/store.py`**：账本追加、工作文件原子替换、越界守卫都在这一个地方。
   想让引擎写到别处，必须先改这一层——那就不是「顺手」能做到的事。
3. **`core` 是唯一与机器相关的层**：状态根、配置、编码。上面的层拿到的是
   `Settings` 与 `StateLayout` 对象，不自己拼路径。
4. **`rules` 不依赖 `engine`**：静态规则扫描是「读文件、比字符串」，与运行时无关，
   所以它能在 CI 里对**没有状态**的仓库跑。

## 数据流（一拍）

```
tick_status.json ──▶ 拍号
        │
        ├─▶ sprout_queue.load()  ──▶ take_topic()  ──▶ （可选）执行器
        │                                                 │
        ├─▶ observe_state()  ◀────── W回 ─────────────────┘
        │
        ├─▶ reconcile(preds, obs) ──▶ diffs（四类）
        │            │
        │            ├─▶ diffs.jsonl（全部，含「预测内对」）
        │            ├─▶ maturity.jsonl（本拍被证实的对象 +1 步）
        │            └─▶ sprout_sources ──▶ sprouts.jsonl（①差异 ②封顶 ③未用）
        │
        ├─▶ outcomes.jsonl（本拍领过的芽：兑现/打脸）
        ├─▶ reconcile/reconcile-<拍号>.md（报告，文件名带拍号）
        ├─▶ org-due.json（组织段是否到期＋理由；拍循环**自己**算，不留给外部调度器）
        └─▶ tick_status.json（心跳：rc / 连续失败 / 时间戳 / 拍号）
```

## 为什么这样切

每一条分层都对应一个**曾经出过的事故**：

| 分层 | 事故 |
|---|---|
| 写盘收口 | 一次截断把半个状态文件洗掉 |
| 状态根参数化 | 状态挂在宿主项目下，搬不走、还泄漏目录结构 |
| 判据与实现分家（`engine/model.py` 单一词汇表） | 同一条规则两处写，两边各自演化到打架 |
| 规则层独立 | 规则只写在文档里，没人每次去查 |
| 提示词同源校验 | 代码删了定义，提示词还在引用它 |
