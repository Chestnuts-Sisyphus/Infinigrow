# 机制正本（单册）

> 本文件是**机制的单一事实源**。代码与提示词都必须与它一致；不一致由
> `python -m infinigrow scan` 的 R2（提示词↔代码同源）与 R3（禁自造芽条款）当场抓住。
>
> 改机制＝改本文件 + 改代码 + 改提示词，三处同改，缺一不可。

---

## 1. 公设

只有两个仓库：

- **B＝认知**（belief）
- **W＝现实**（world）

一切结构都是两者之间的**边**：

| 边 | 方向 | 一句话 | 「长了」的机械判据 |
|---|---|---|---|
| **判读** | W→B | 看懂现实 | 该对象的预测在下一次对账中被现实证实 |
| **行动** | B→W | 会做 | 动作执行后 W 侧对象发生**可查**变化 |
| **原理** | B→B | 想通 | 推出的认知在**从未测过的域**被验证 |
| **固化** | W→W | 自动 | 同类输入**不再烧认知**（不必再想） |

**现实是唯一裁判**：判断不由引擎自述，由现实对账定；判断本身也要进账（可被打脸）。

**成熟链**：一条经验从生到熟走四步 —— 判读 → 行动 → 原理 → 固化。
第 4 步（固化）＝封顶；封顶不是死锁，而是**新入口**（见 §4 芽源②）。

## 2. 一拍做什么

```
组织会话（可选，需要执行者）→ 定 B猜 → 取题（队列排序）→ 动手（执行者，可选）
→ W回（**动手之后**再读现实）→ 对账 → 差异 → 域饱和闸 → 生芽 → 记账 → 心跳
```

- **B猜**：动手前写下的可对账承诺（对象 / 维度 / 预期态变 / 指针）。
- **W回**：动手后现实侧的可查回答（账本行 / 文件 / 日志）。
- 顺序是机制的一部分：W回 必须在动手**之后**——动手前读的现实，证明不了动手的效果。
- 对账是**机械**的：按 `(对象, 维度)` 对齐，`预期 == 实际` 即判「对」。
  语义型（事件、意图区硬冲突）的判断归组织会话，判断进账、可被打脸。

### 2.1 引擎在长什么（生长主体）

引擎动手的地方是**生长主体**（growth subject）：一个目录，默认在仓库**同级**
（`IG_SUBJECT_ROOT` 可指到任意目录）。主体对象一律命名 `主体/<相对路径>`。

- 机械观测只读这些可查事实：主体根的存在性与文件数、**每个子目录的文件数**（目录对象
  `主体/<相对路径>/`，N43：结尾 `/` 是判据，与同名文件对象永不撞名）、每个文件的
  存在性与字节数（有界、稳定排序）；
- 没有主体＝没有靶：机械拍只能观测自己的状态文件，那不是生长（上一代的病根之一）；
- 引擎代码与主体分家：升级引擎不动生长痕迹，开源不带出主体。详见 `docs/zh/growth-subject.md`。

**观测面有界（判据写死，不是「大概」）**：

- 逐文件观测最多 `SUBJECT_FILE_LIMIT＝20` 个（按 **mtime 最新**取，旧的不会永久霸占名额；
  「文件数」维度始终是**真实总数**，不受这个上限影响——N42）；
- 逐目录观测最多 `SUBJECT_DIR_LIMIT＝10` 个（按**名字**升序取前 10，N48-5/M6）。超出观测面的
  目录**不进可对账清单** → 对它的提议/发现会被对象名机械闸拒收（`valid_subject_object`）。
  当前主体只有 2 个目录（journal／archive），离边界很远——这是**已知边界**而不是隐患藏身处：
  到了 10 个目录那天要改的是这条判据（改判据＝改文档＋代码＋测试），不是顺手调个数字；
- **定键补观测**（M7/N45）：预测里出现过的键若被上面的名额边界挤出去，观测侧**补一条**
  （只 stat 这些键，不扩观测面）——否则新增文件会把边界文件挤出名额，它被记成
  「预测未执行」（它其实存在，实测 8 行假差异：拍 267/271/272/274/290/302/306/311）；

**对称律（实测换来的）**：预测与观测必须**同对象同维度**。少一边就会凭空造差异——
观测 6 个文件却只预测 3 个 → 每拍 3 条「预测外发现」；观测了文件存在性却不预测它
→ 每拍「预测未执行」。两种都会让引擎给自己派无解的活，所以：

- **引擎自身状态文件不进对账**：那些文件是引擎自己写的，每拍都因自己的记账而变；
  把它们当差异读＝自己给自己派活。引擎自身健康由**园丁**看护（断流/锁/失败计数/轮转）；
- **默认预测/观测只覆盖主体**；显式传入 `predictions`/`observations` 时按传入的来
  （测试与嵌入用）。
- **成熟链同拍每对象最多 +1**：一个对象一拍可能有多条被证实的差异（存在性＋字节数），
  逐条推进会让它一拍 +2——所以推进前按对象去重。
- 组织会话**可以**对「主体内尚不存在的文件」下预测（预期=存在）：现实读不到它 →
  「预测未执行」→ 照样产芽——这是「该创建它」的**合法提议路径**。但它**不许发明**
  机械层读不到的对象名（首拍实测：凭空写了个不存在的对象，直接制造一根假芽）。
- **扫现实的对比窗口＝「自上次组织会话以来」**（K14/N55/N58）：组织会话的输入块
  「本拍现实变化」比的是**锚点**（`subject-org-anchor.json`＝上次它跑时读到的清单）
  与**此刻清单**之差——消费者是它，它就该看到自己缺席期间发生的事（它每 3~5 拍才跑一次）。
  两次踩过的坑：①「上一拍快照 vs 本拍清单」两者之间什么也没发生 → **恒为空**（N55）；
  ②改成「上一拍动手前后」后窗口只有 1 拍 → 天然错过其余几拍（实测七次全空，N58）。
  另外触发判据④要求「上一拍安静」，而生长拍必写非「预测内对」行 → 经 ④ 触发的会话
  窗口永远安静（两者反相关）——这也是窗口必须拉长的理由。条目＝
  新出现／有变化（字节数变了）／从清单里消失／目录格数变化；
  锚点缺失（首次跑／旧状态根）→ 退回「上一拍动手前后」并把窗口如实写在行里，不假装看过。
- **提议「再长一格」用目录对象＋差额**（N43）：`主体/<目录>/`｜`文件数`｜`+1`。
  名字里的拍号段是**创建拍**的（K7），提议方猜不到未来的创建拍——点名必然对不上
  （实测：提议 `journal/0257-….md`，执行者在拍 291 建出 `0291-….md`，芽连领 3 拍耗尽）。
  差额承诺的是「再推进一格」，引擎在**动手前**把它锚定成绝对值
  （`resolve_relative_predictions`），所以目标不会过期。反向不成立：现实**已经超过**
  预期（预期 < 实际）时，不把旧预期派回去（那会让执行者把现实改回错的样子）。

### 2.2 执行者通道（谁在动手）

「动手」由**执行者**完成：提示词经 stdin 进、stdout 出（`IG_EXECUTOR` / `--executor`）。
不给执行者＝机械拍：零 token、零凭据、不出网。四种失败（非零退出／超时／空输出／起不来）
全部记账，并进心跳的「执行者连续失败」计数（与拍失败分开计）。详见 `docs/zh/running.md`。

### 2.3 组织会话（语义段）与它什么时候跑

**组织会话**是唯一允许语义判断的地方（意图、硬冲突、「下一步该长什么」）。它需要执行者通道；
没有执行者就永远不跑。

四条触发判据**任一**成立即候选（冷却闸在最后拍板）：

| # | 判据 | 读法 |
|---|---|---|
| ① | 从未跑过 | 组织段账本 0 条 |
| ② | 空窗 | `当前拍 − 上次组织拍 ≥ org_gap_ticks`（5）|
| ③ | 待补指针差异 | 条数 > 0 |
| ④ | 「安静」 | 差异账尾部连续「预测内对」**行数** ≥ `zero_gap`（10）|

**单位诚实（N56，[已证明]）**：④ 数的是**账本行数，不是拍数**。安静的一拍写 ~40~43 行；
生长拍必写至少一条非「预测内对」行 → 计数清零。实测最近 40 拍（400–439）：读数要么
~40~43、要么 0，其中 **14/40 拍**达到 ≥10。所以 `zero_gap = 10` 的真实语义
≈**「上一拍安静」**（约 0.23 拍），不是「连续十拍安静」。标签已在 v2.2.9 改成说「行」。
**语义定案：保持行数口径（N58-① 收口，2026-09-19 [已证明]）**。字面改成「连续 10 拍安静」
**不是「慢一点」，而是近乎永不触发**：生长拍必然写非「预测内对」行并把串清零，本机实测
拍 556–628（差异账尾部窗口 73 拍）里安静拍只有 **14/73＝19%**，而**最长连续安静＝1 拍**、
`≥10` 连续安静 **0 次**。要重开这条，得改「什么把串清零」这个判据本身
（代码＋测试＋中英正本一起动），不是调 `zero_gap` 的数字。

**实测节奏（[已证明]）**：冷却闸给的是 30 分钟一次，实测间隔**中位 40.0 分钟／均值 42.3 分钟**
（`state/org-llm.jsonl`，100 个间隔，手工跑的 <10 分钟已剔除）。原因是结构性的：④ 只在
**安静拍**之后才可能成立，而真正推动主体的生长拍必写非「预测内对」行 —— ④ 与生长**反相关**
（N58）。有效节奏 ＝ 冷却闸 ＋ 等一个安静拍。

**「上次」的单位是一次组织段尝试，不是一次调成 LLM 的调用（[已证明]，本机实测 2026-09-19）**：
①②与冷却闸读的都是**组织段尝试账**，而写入只发生在组织段**真的起跑之后**的三条路径——
提示文件缺失（那次没碰执行者）、执行者调用未成功（rc≠0／超时）、正常跑完。前两条让
「试过」≠「调成过」。**没接执行者时组织段根本不跑，也不写这一行**：实测 `IG_EXECUTOR=""`
的新状态根连跑 3 拍后 `org-llm.jsonl` 不存在，`org-check` 仍报「①从未跑过组织段」——
纯机械部署不会自己把自己节流住。（**上一版这段写的是反的**：它说「只跑机械拍的根拍 1 也会
写一行」，那是把一次**带着 `IG_EXECUTOR` 环境变量**的调试跑当成了无执行者现场。）
后果因此有了更准的边界：**接了执行者的那一拍**——包括手动拍一拍做调试——会占住冷却窗，
把下一次真正的 LLM 组织段推迟至多 `org_cooldown_min` 分钟。**语义定案（2026-09-19）：保持
「尝试」口径，不改成「只有调成 LLM 才算一次」**。理由：失败的那次调用若不算一次尝试，
冷却闸就挡不住每拍重试同一个坏掉的执行者，①②③④ 会再次全部放行——等于拿 token 去换一
个已知失败的调用，而那条闸正是为节流装上的。

## 3. 差异（唯一的主芽源）

四类（不许发明第五类）：

| 类型 | 判据 | 产芽 |
|---|---|---|
| 预测内错 | 预期态变 ≠ 实际态变 | ✅ |
| 预测内对 | 预期 = 实际 | ❌（计入被验证） |
| 预测外发现 | 实际有、预测没提 | ✅ |
| 预测未执行 | 预测写了没做 | ✅ |

**证据指针强制**：每个差异点必须带来源指针；无指针 → 进「待补指针」区（机械登记，不丢），
超过宽限拍数仍未补 → 「指针缺失」差异 → **照样产芽**（拒收≠丢弃）。
粒度按**对象 × 态变维度**切：同一对象的同一维度错＝1 个差异；两个对象＝2 个。

## 4. 芽（只有三个来源）

> **零差异零芽。** 没有差异、没有封顶、没有未用条目 → 本拍不产芽。
> **执行会话不自产芽**——这是 v2 的实现层结构保证：`engine/tick.py` 里没有这样的入口。

| 芽源 | 机械判据（可查） | 芽题面 |
|---|---|---|
| ① 差异对账 | 带指针的差异点 | 消解这个差异 |
| ② 成熟链封顶 | 对象**本拍恰好**到达第 4 步 | 基于它**开应用面** |
| ③ 能力库未用 | 条目 `拍号差 ≥ 阈值` 且最近执行者留痕里未出现 | 它**为何没用上**／别域是否成立 |

②③ 是 v2 新增的现实入口。v1 只有 ①：差异被消解完后，队列只剩执行会话自造的复述芽
（实测 221 根待长里 186 根同族、题面逐字相同），引擎于是原地打转。

**③ 的判据输入必须是真读数**（N48-1/N48-2 的修复）：`last_used_tick` 有**真实更新方**
——执行者留痕里命中该条目名 → 记为已用（不再「创建那一拍写一次、此后永久为真」）；
「本拍用过」这道闸读的是**执行者留痕输出**（最近若干份），不再读差异账的 `note`
（那道闸此前形同虚设：实测那串文本总长 19 个字符）。

**提醒必须有出口**（N48-3，与去重同批落地——只修去重＝把这条渠道断电）：

| 出口 | 判据 | 动作 |
|---|---|---|
| **消费** | 条目名出现在执行者留痕**输出**里 | `last_used_tick` 更新；该条目在队的芽退场（只移动进冻结区），不再被问 |
| **结案** | 被问满上限（复用连领上限 N＝3）仍无消费 | 库账本写 `closed_tick` ＋结案指针（指向最后一次被问的留痕）→ 条目**移出候选池**，不再产芽 |

为什么非有不可：「可用性」是**机械层读不到**的维度（兑现账只能如实标 `verifiable=False`
——已 240 行），没有出口它就是一条永真、可无限重生的提醒：每拍重立 ~36 根，把上限 50
的队列占满，主芽源「差异对账」自 tick 189 起零取题，能做完的差异芽全被挤进冻结区。

**队列纪律**：

- 同对象同维度＝**一根**芽（新顶旧）；不同维度才各算一根。
  **重提不改问题的年龄**（Q1/A1）：新芽继承旧芽的**出生拍**（取更早的那个）与
  「最后一次被碰的时刻」，所以一个等了很久的问题被重提之后**不会变回刚出生**、也不会
  因为合并而插到队首。**连领计数不继承**：它是记录行的额度，继承了等于让重现的差异
  在问满 3 次后被永久判死——新记录行照旧拿自己的预算。
- **去重含冻结区**（N48 的真凶修复）：某对象在活跃队列**或冻结区**里已有一根芽时，
  不再立新的——「挂起≠死亡」是这条合并律的另一半：冻结的芽还是那个问题的芽。
  只扫活跃队列时，被挤出的同一对象下一拍又被当成「没生过」重新立芽（实测：库 91 条
  条目**全部**已有芽，却每拍再立 ~36 根）。
- 活跃队列上限 50；超限＝最旧的进**冻结区**（只动队列，账本全留）。
- 同一根芽最多连领 3 拍；冻结区可**重新点亮**（挂起≠死亡）。
  **连领上限没有任何后门**：曾登记为预留（K16）的 `long_task` 豁免已于 2026-09-19 **退役**
  （登记见 `docs/superseded.md` S9）——它从来没有写入方（拍 647 实测：活跃 48 行＋冻结 4,322
  行，全部带这个键、**0 行为 true**），而一个「读旧行就会放行」的分支留着，就等于让那条由
  事故换来的上限随时可以被一次赋值变成建议。旧账本行里残留的 `long_task` 键不报错
  （`Sprout.from_record` 忽略多余键），但**不再产生任何效果**；`tests/test_sprout_queue.py`
  盯住两件事：源码里不许再出现这个字段，带标记的旧行也不许换来豁免。要恢复它，先按
  `docs/superseded.md` 的流程给出「什么算长任务」的机械判据。
- **冻结芽的重问判据**（M4/G9）：冻结不是**永久封存**。某对象**最近一根芽**也已冻结满
  `frozen_requestion_ticks` 拍（默认 300）且未被点亮（＝没回到活跃队列）→ 不再拦它，
  允许重新立芽。判据取「该对象全部冻结芽里最新的那次冻结」：只要还有一根是新近的，
  就说明刚被问过，不重复立——否则积压的旧冻结芽会在同一拍把同一批对象全部放行（洪泛）。
  `frozen_tick`＝被挤进冻结区那一拍（升级前的旧行没有这个字段 → 回退到 `created_tick`，不假装它刚冻结）。
  默认 300 的理由：队列在健康差异速率下约一天翻一轮，两天的冷却保证「被推后的问题」不与
  新问题抢取题位；91 条条目 / 300 拍 ≈ 0.3 根/拍，低于差异芽的到达速率（不反客为主）。
- **冻结区重看节奏**（T4/A5）：每 `frozen_review_every` 拍（默认 20）扫一次冻结区，
  给其中的芽一次**重新点亮**（回到活跃队列）的机会。它与上一条**分工不同**：
  重看＝把冻结的芽捞回队列（判据是拍数，不看对象），重问＝允许对同一对象**重新立芽**
  （判据是「该对象最新那次冻结」的年龄）。这条此前只在代码里跑、正本没写，
  所以使用者无从知道 `IG_FROZEN_REVIEW_EVERY` 存在。
- **冻结区有容量判据**（M5/N48-4）：行数超 `frozen_cap`（默认 5000）时把**最旧的**
  移动进 `state/archive/files/frozen/`（保留尾部 `frozen_keep_tail`＝4000 行）。
  与账本轮转同一套纪律：**只移动不删**，先落归档件再缩主件。
- **容量轮转跑不到重问窗前面**（G5 附带核对，2026-09-19 拍 713，状态根副本实测）：冻结区
  4,373 行、距 `frozen_cap` 还差 627 行；新增速率按窗口不同在 **0.66 行/拍**（近 50 拍）到
  **1.50 行/拍**（近 100 拍）之间 → 触 cap 还要约 **418～950 拍**（本机实测拍频约 10 分钟）。
  而轮转之后仍留 4,000 行＝覆盖 **≥2,600 拍**历史，远大于 300 拍窗口所需的约 200～450 行——
  所以**不存在「一行还没被重问就被移出冻结区」**：被移走的必然早已跨过窗口（当前该占 92.8%）。

**域饱和**（T7）：同一「对象域 × 标准可验证量」只养**一根未完成芽**。

- 对象域＝对象名里最后一段 `/` 之前的部分（没有 `/` 的对象**自成域**，
  于是退化成上面那条既有的合并律，不误伤旧行为）；标准可验证量＝差异的维度。
- 饱和时的重复差异**不新生芽**：登记为已有芽的 `absorbed` 计数；
  差异本身**照旧入账**（打标 `absorbed_by_domain`）——配额不是隐藏。
- 解冻条件（四条，任一即释放占用、允许再立一根）：
  ① **产出了新的量**（新差异的 actual ≠ 立芽时的 actual）；
  ② 该芽**被消解**（本拍对账为「预测内对」）或**已不在队列**；
  ③ **持有者芽已耗尽**（连领满上限且非长任务，永不再被领）——这个域的问题没人再管了；
  ④ **差异对象 ≠ 占用对象**——同域同量下的**另一个**问题（例如 journal 下一篇），
     视为新量，不再被旧占用吸收。
  （③④ 是 N41 死锁的修复（K1）：`存在性` 这类有穷枚举维度「产出新量」几乎不成立，
  若持有者又已耗尽，该域会被永久占用、新差异全被吸收、引擎停摆。）
- 同拍内也守配额：一拍里同域同量的第二条差异同样被吸收（否则「一批差异」就能绕过它）。

## 5. 账本（追加型，只增不改）

**兑现率＝现算**，且**诚实呈现**（T11/G6）：

- 分母只数 `sample=true` 的行（那一拍**真有执行者动手**）；
- 一行样本都没有时，报告写「**无样本**」——兑现率**不可计算**，
  不是 0、更不是「差」（机械拍不做语义判断，也不产出真实生长）。

**打脸的三分口径**（M10/B2/B3/Q6）：可对账样本里判「打脸」的行，按**原因**分开报——
分错一笔就是把执行者侧的故障记成提议的账：

| 桶 | 判据 | 证明等级 |
|---|---|---|
| **执行者侧未落地** | 两条执行者侧证据任一成立：① 该拍留痕里带「输出未解析」的**字面标记**（适配器自己打了诚实行：整条回复被当成最终留痕、动作没执行）；② 该拍**每次** tick 调用都非零退出／超时（`state/executor.jsonl` 的 `rc`／`timed_out`；同拍只要有一次 rc=0 就不算，组织段调用不算在芽的账上） | [已证明]（字面标记与退出码都是机械读数） |
| **提议过期** | 领做时芽龄 ≥ 30 拍（出生拍取自芽 ID 拍号段）——提议的前提已老。**没有**任何证据证明「提议内容已失效」，故它是**机械代理·待证**，且只在执行者侧两条证据都不成立时才落到这个桶 | [归纳待证] 的**机械代理** |
| **真没做** | 芽龄 < 30 拍，且两条执行者侧证据都不成立 | [已证明]（判据同上） |

现场（[已证明]，2026-09-17 拍 449）：模型回了带 `actions` 的 JSON，但**开头少了 `{"`** →
适配器 `extract_json` 失败 → 整条回复（含写入动作）被丢弃 → 引擎如实记打脸。
那一条的芽龄是 59（≥30），按芽龄会被记成「提议过期」——**那是记错账**。
所以给了 `traces_dir` 时，「执行者侧未落地」优先于芽龄分桶。整条链路上**引擎侧的记账是
诚实的**（文件真的不存在 → 打脸成立）；丢的是执行者侧那一次动作。

**第二个现场（[已证明]，2026-09-19 拍 723）**：那一拍 `state/executor.jsonl` 有一行
`rc=1`、`usage=unknown`、note「非零退出（stderr 见留痕）」，同拍 `outcomes.jsonl` 的
`sp0695-051-主体_journal_0690-20260919` 是 `verifiable=true`、`redeemed=false`。留痕里
**没有**「输出未解析」标记（那是解析失败的形态，非零退出时适配器不会打它），所以只看标记的
规则把这行判成了「真没做」——**把执行者侧的失败记在主体的账上**。因此执行者侧证据有两条：
标记，或该拍每次 tick 调用都非零退出／超时。真库对照（`python -m infinigrow redemption --json`
在拍 730 现跑）：拍 723 由「真没做」改判「执行者侧未落地」，拍 499／521 两条不动（当日
`rc=0`），拍 676／679 仍走标记那条证据；**分子分母一字未动**（318 样本／311 兑现／7 打脸／
363 不可对账），归因只动打脸行的分组。

**固化边**（T6/A7）：成熟链封顶芽（`cap*`）的维度「应用面」是**语义维度**，机械层读不到
——所以这条边**默认**判不出兑现（[已证明] 现场：累计 160 次领做、`verifiable=true` 0 条，
最近 30 拍占 24/31 个取题位 → 兑现率的分子系统性缺一角）。

**现在它可对账了（Q2/A3）——靠一份「应用证据件」**：

- 约定的路径由**引擎**规定，并**逐字写进那一拍的题面**（不让执行者猜命名）：
  `app/<领做拍号4位>-<对象名>.md`（对象名里的 `/` 换成 `_`；
  例：芽 `cap0380-001-主体_journal_0376-20260916` 在拍 438 被领做 →
  `app/0438-journal_0376-20260916.md`）；
- 引擎对该路径下**一条预测**（`存在性＝存在`），并按 M7 定键补观测真去读它 →
  **证据件存在＝这一手应用真的发生了**：该行 `verifiable=true`、兑现/打脸按它判，
  并**进兑现率分母**；
- 它是**记录**不是域对象：不产芽（失败不堆不可完成的芽）、不进成熟链、不进能力库；
- 没留证据件的那一拍，判据是「读得到但不存在」——**是「没做」，不是「读不到」**。

**缺失要分三类，不许混成一桶（G2，2026-09-19）**：`infinigrow status` 与对账报告的那行
「证据件合规率」带**缺失归因**——**自述已写未落地**（该拍留痕输出段里执行者自述写了**同一个**
约定路径、文件却不在）／**命名漂移**（自述写到**别的名字**，连拍号差 1 也算，必须被抓住）／
**未自述写入**（没留痕、或那一拍根本没自述写 `app/`）。判据只读留痕的**输出段**
（`reconcile.trace_write_paths`）：约定路径本来就由引擎逐字写进题面，扫全文等于让引擎给自己作证。
**本次逐条取证推翻了一个猜测**：曾怀疑「命名错配把假打脸送进分母」（预测 `app/0676-…`、
实存 `0677-app_0637-…`）。实测不成立——主体 `app/` 现存 174 件，**每一件**都能由某个 cap 行的
（对象, 拍号）用同一路径函数重算得到（**孤儿 0 件**）；近 30／40／60 次 cap 领做的缺失归因都是
「自述已写未落地 2／**命名漂移 0**／未自述写入 0」，那两行（拍 676、拍 679）的自述路径与题面
**逐字相同**、rc=0，文件却没出现——是**动作没落地**，不是名字对不上（执行者侧损耗，属另一条线）。
归因**不改分子分母**（兑现率算法一字未动），只把「掉的是哪一分」变成机械可读的事实。

仍未接证据边的 cap 行（旧账与不带题面的调用）：照旧标 `verifiable=false`、
**不计入分母**、也不算「打脸」（读不到 ≠ 打脸），对账报告里**单独列出**（`固化边` 段）。
`cap*` 芽占取题位仍是刻意的：封顶芽驱动执行者把已固化能力**应用到别域**（一个真动作）。

**判读边与可用性边现在也可对账了（R1/A1、A2）——靠「留痕点名」**：

- 与 cap 边同形的问题：差异源的 **`判读`（READ）边**（现实给了新东西而没预测到 →
  先看懂它）的对象是「预测外新出现」的旧 journal 文件——领做那一拍它已滚出
  「mtime 最新 N」的观测名额（`SUBJECT_FILE_LIMIT`）→ `(对象, 维度)` 不在
  `observable_keys` 里 → 如实标 `verifiable=false`、**永不可翻**（实测近 30 拍
  8/9 不可对账，占着取题位）；能力库「可用性」边（`lib*`）同病（历史 179 行全不可对账）；
- 修法（零新文件）：兑现判据改读**本拍执行者输出**里对**源对象**的字面点名
  （全名 `主体/<相对路径>` 或主体内相对写法 `<相对路径>`；目录对象只认全名）——
  与 M3「留痕命中＝已用」**同一段输出、同一套命中判据**（`entry_mentioned`）；
- **命不中是可机械判的**：这两条边的 `verifiable` 恒 `true`、未点名＝如实记打脸
  （读得到却留不下文字，是「没做」，不是「读不到」——与固化边的证据件判据同构）。
  它判的是「读了并留下文字」的**机械事实**，不是「读懂了」的**语义事实**
  （语义归组织会话判断段）；判据输入**只含输出段**（不含提示词——提示词里点着
  对象名，算进来就成了自证）；
- 调用的每一拍题面会写明这条判据（与 cap 芽条款对称，执行者不靠猜）。

**这份长跑支撑到哪一层兑现率研究（[已证明]，2026-09-18 拍 624 现场）**：

- 全局读数：575 行领做、**212 行可对账样本**、兑现 208 → 兑现率 **0.98**（Wilson 95% 区间
  0.95–0.99）。报这个数必须带着分母占比：**363 行（63%）`verifiable=false`**，不在分母里。
- 分桶轴是「对象域 × 预测边 × 实际边」，**成熟步不是现算口径的一轴**：兑现账的行没有步字段，
  要按（对象, 拍号 ≤ 领做拍）与成熟链账 join 才拿得到。join 之后 212 个样本**全在第 4 步
  （封顶）**，第 1/2/3 步**无样本** → 「第几步的预测更准」当前**不可计算**（不是 0）。另有
  42 行样本的对象名在成熟链账里查不到（两账对象命名口径差），join 前须先归一。
- 芽源覆盖不齐：`固化`／`判读`／`行动`／`原理` 四条边都有样本，而能力库芽源（`lib*`）历史
  179 行全在留痕点名修复之前 → 该芽源的兑现率仍是**无样本**。
  - **这条无样本的到期复测 ETA**（G7，2026-09-19 拍 713 快照）：28 条待问**全被挡**（重问冷却
    28、未到闲置阈值 17），最早可重问拍 **892**（挡住的那条冻结于拍 592，还差 179 拍）；本机
    实测拍频约 10 分钟 → **约 2026-09-20 晚间**到点。到点要量的不是「有没有出芽」这一格，
    而是整条链是否真在流动：**待问 → 出芽 → 取题 → 结案/消费**；复跑读数是
    `infinigrow status` 的「能力库渠道判定／重问闸」两行 ＋ `infinigrow redemption --json`
    里 `lib*` 那一桶有没有进分母。在那之前，「能力库未用」这条芽源的兑现率**继续记无样本**，
    不许拿 0 或 1.00 冒充。
- 打脸的形状：4 行打脸＝执行者侧未落地 3 ＋ 提议过期 1 ＋ **真没做 0**；且**没有一行**是
  「预测边 ≠ 实际边」。所以这份数据回答的是「说了要做、有没有真做」，**回答不了「边选没选错」**
  ——后者要等选错边的样本出现才有分母，0 例不能外推成 1.00。
- **可行性判定**：格式与口径**已具备**（现算、分桶、打脸三分归因都跑得动，
  `infinigrow redemption --json` 可复跑）；再往「判断准不准」那一层走，缺的不是拍数，
  是**能被判错的样本**。

**轮转**（T6/G7）：账本只增不减，历史由**轮转**搬进 `state/archive/`（**只移动不删**）。
保留策略按账本语义分两种：历史型（差异/兑现/执行者/组织）保留尾部 N 行；
状态型（成熟链/能力库）**每个键保留最新一行**——否则很久没碰过的对象会随轮转悄悄倒退。
归档可检索（`infinigrow rotate --search <关键词>`）。**冻结区**（`sprouts-frozen.jsonl`）
走同一套：超 `frozen_cap` 把最旧的移进 `state/archive/files/frozen/`（M5）。
**日志轮转归启动器**：调度器（`tools/run_tick.bat`）以追加句柄持有 `logs/tick.log`
贯穿整个 tick 进程（Windows 下该句柄既不共享删除也不共享写入，进程内删不清）——
轮转由 `tools/rotate_journal.py` 在**两拍之间的句柄空隙**执行（打开任何句柄之前）：
超阈值把原内容**脱敏**（抹除本机路径，归档件是可迁移产物）后整体写进归档件，
再清空主件供本拍追加；只移动不删、数据先保险后清空。

**信条**：会话可抛，账本持久——生芽/选芽会话每次都是新的，账本是唯一的记忆，
所以每次增益预测都必须带兑现率引用。

## 6. 目标隔离（激励相容）

| 角色 | 业绩（账本现算） | 业绩里**不**包含 |
|---|---|---|
| 执行会话 | 预测精准（B猜被 W回 证实的比率） | 生芽数量、分岔多少 |
| 组织会话 | 生芽合理 + 增益预测精准 | 取了多少题、选了哪根芽 |

不靠藏机制，靠**业绩定义**让两边没有掺假动机：多生芽不是业绩，生芽的**合理性**才是。

**组织会话要有运行体**（T3/G3）：判据与提示词写好了但没人调用，等于不存在
（上一代的 P0 根因）。所以它是一段真代码（`engine/org_session.py`）：走执行者通道，
输入是 B猜＋留痕＋W回，输出是四类差异与规划预测；发现进 `org-findings.jsonl`，
**结局由后来的对账现算**（`org-status`：待验／被证实／被推翻）——判断不由引擎自述。

## 7. 保真与守护

- **保真闸**（全机械）：能不能真跑、能不能真验；不过闸不发题。
- **断流判据＝机械时间戳**：最后一拍距今多久，由心跳文件的机械时间戳算，不用模型自述。
- **失败必须可见**：心跳写不进去 → 抛 `TickHeartbeatError` → 进程非 0 退出（不许静默）。
  执行者的失败（非零退出／超时／空输出／起不来）另有独立计数与告警旗。
- **同拍步进上限**：成熟链 `+1` 硬编码，拒绝单拍连跳。
- **并发**：`locks/` 独占锁；报告文件名带拍号。
- **写盘只有一条路**：`ledger/store.py`（越界守卫 ＋ 原子替换）；
  由静态规则 **R8** 守住（`src/infinigrow` 里除白名单外出现直接写盘即 FAIL）。
- **退出码单一来源**：`core/exit_codes.py`；CLI 里出现裸整数（≥2）由规则 **R7** 判 FAIL。
- **版本闸**：运转前过闸（默认用最新版；升不动就按现有版本照常跑）——见 `docs/zh/upgrading.md`
  与 `docs/zh/running.md`。

## 8. 与提示词的同源

机制词（判读/行动/原理/固化/成熟链/差异/兑现账/成熟链封顶/能力库未用/零差异零芽/
**生长主体/执行者/组织会话/域饱和/轮转**）在**代码**与**提示词**两侧都必须存在——
表定义在 `src/infinigrow/rules/static_scan.py` 的 `SYNC_TERMS`（单一事实源），
由 `tools/check_prompt_code_sync.py` 双向校验；规则 **R9** 再守住**表的覆盖下限**
（有人静默删词＝漂移面回来了）。这是 v1「同一件事两套规则并存」那个病根的
**结构性防复发手段**。

## 术语表

机制词的中英对照。这些词在**代码、提示词与账本**里都是标识符；**中文形是正本**
（英文文档是它的说明书，见 `docs/mechanism.md` 的同一张表）。

| 中文 | English | 含义 |
|---|---|---|
| 判读 | read | W→B 边：看懂现实 |
| 行动 | act | B→W 边：让现实发生可查变化 |
| 原理 | principle | B→B 边：推出新认知 |
| 固化 | solidify | W→W 边：同一类输入不再烧认知 |
| 成熟链 | maturity chain | 判读 → 行动 → 原理 → 固化，四步 |
| 差异 | difference | 预测与现实对账出来的缺口 |
| 预测内错 | predicted-wrong | 预期态变 ≠ 实际态变 |
| 预测内对 | predicted-right | 预期 = 实际（被证实） |
| 预测外发现 | unpredicted finding | 现实有、预测没提 |
| 预测未执行 | not executed | 预测写了没做 |
| 兑现账 | outcomes ledger | 每根被领做的芽一行 |
| 兑现率 | redemption rate | 可对账样本里兑现的比例 |
| 芽 | sprout | 一个可被独立消解的差异（工作单位） |
| 芽源 | sprout source | 差异对账／成熟链封顶／能力库未用 |
| 差异对账 | difference reconciliation | 芽源① |
| 成熟链封顶 | maturity cap | 芽源②（到第 4 步） |
| 能力库未用 | unused capability | 芽源③（库条目闲置） |
| 零差异零芽 | no difference, no sprout | 芽经济的硬规则 |
| 冻结区 | frozen zone | 被挤出的芽挂起的地方（不是删除） |
| 重问 | re-ask | 冻结满年限后再问一次 |
| 结案 | closure | 让提醒永久结束的出口 |
| 生长主体 | growth subject | 引擎在长的那个目录 |
| 目录对象 | directory object | `主体/<路径>/`，量＝文件数 |
| 执行者 | executor | 动手的那一方（提示词经 stdin 进、stdout 出） |
| 组织会话 | org session | 语义段：对账、提议、立 finding |
| 域饱和 | domain saturation | 一个域 × 量只能有一根未完成芽 |
| 轮转 | rotation | 旧账本行移进 `state/archive/` |
| 定键补观测 | keyed supplemental reading | 补读被挤出观测面的预测键 |
| 观察面 | observation surface | 机械可读事实的**有界**集合 |

英文公开文档：`docs/mechanism.md`。
